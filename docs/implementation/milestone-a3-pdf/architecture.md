# A.3 Stage 2 — PDF structure and provenance

This service applies to Library Sources only. It consumes the existing PDF layout collector and `generated_contents::headings`; it neither changes shared extraction/recognition rules nor marks any Bible import as verified. `sections::has_sections()` still excludes PDF. Literal mentions, source-only section evidence and user-confirmed links remain separate.

New imports collect layout once for normalization and structure. The managed copy is stream-hashed before commit, so a file changed after preview cannot attach metadata to different bytes. Internal PDF outlines and aligned tagged headings take precedence at the same original line. Tagged paragraphs, quotations, lists, notes and artifacts are retained where text alignment succeeds. Layout fallback uses the existing conservative heading detector plus repeated margin furniture and line roles. Unknown structure stays unknown; unsupported tags/ambiguous alignments are not fabricated into targets. Existing imports require an explicit **Document structure → Build structure** action, avoiding an expensive all-library rebuild at startup.

Each proposal retains source/file SHA-256 identity, immutable segment position and UTF-16 offsets, physical page, original line text, original coordinates/type size/column, hierarchy, and evidence (`outline`, `tagged`, `layout`, `user`). PDF PageLabels supply printed labels where present. Exact unique text alignment is required before a proposal acquires a stored-text target. A bookmark can have a different title from the drawn heading; the title is metadata, never substituted into source/citation text. Internal destination coordinates can align such a bookmark only near an actual original line. External actions are not followed.

Passage mappings use existing six-language address dictionaries, explicit heading references, or numeric headings under grounded biblical-book context. Body citations do not establish a book context. A structured PDF's exact/range and chapter section starts precede book fallback, followed by contextual body mentions and incidental notes. Running furniture is excluded from passage results. This says where a heading names Scripture, not whether its author offers genuine commentary or a sound theological relationship. Generic EPUB/DOCX/unstructured-source rules retain their existing ranking.

Reading displays heading spans and text roles over unchanged text. The DOM retains the same UTF-16 quotation/annotation offsets. A target inside an existing paragraph scrolls to the heading span. Corrected Contents uses segment targets; unaligned supplied PDF page bookmarks remain accessible in a separate, labelled disclosure. A late response cannot replace corrected Contents with raw bookmarks. Original resolves section targets to the original physical page and anchored vertical position. Original-to-Reading uses the nearest available aligned segment. This is line/paragraph precision, not a claim of exact glyph-box equivalence for complex typography.

Corrections edit titles, levels, mappings, exclusions, or add a section at an unambiguous visible original line. Changes update derived links in the same transaction. Empty user mappings stay empty. Undo retains 20 previous correction sets; Reset is itself undoable. Rebuild preserves corrections/history and never replaces segment IDs, stored text, citations, annotations or reader records. The whole-database backup includes metadata and history; permanent Source deletion removes it. A corrupt optional overlay leaves ordinary stored-text Reading usable and is reported when opening the structure panel.

Bounds: 120,000 original lines, 8 million text characters, 5,000 heading proposals, depth 12 for outlines and 32 for tagged markup, bounded destination/tag walks and 3,000 tagged pages. Incomplete extraction, uncertain page order and unaligned tags are surfaced. A two-document immutable-revision cache prevents repeated JSON parsing as the reader pages. Passage indexing sweeps blocks and active sections; reader overlays are limited to the requested text window. These bounds are not quality guarantees for every publisher's PDF.

## Additive schema 27

Migration `0027_pdf_structure.sql` adds `source_pdf_structures` (document, file identity, revision, corrections/history) and nullable evidence columns on `source_passages`. No existing row is rewritten by this migration. Historical SQL 1–26 is unchanged. The existing pre-migration backup protects a schema-26 profile; the upgrade, foreign keys, failed-migration rollback and full backup/restore are regression-tested with invented data.

An older schema-26 executable must not open an upgraded database. To revert, restore the pre-upgrade backup into a separate profile using the matching executable. Do not copy only the SQLite main file while the application is running. This branch adds no updater, commerce service, cloud sync, or recognition merger.
