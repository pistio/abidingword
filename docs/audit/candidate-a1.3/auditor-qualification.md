# Independent corpus-auditor qualification (pre-Set H)

**Status:** suite authored; **not yet executed in a provisioned repository checkout**. Its existence is not a passing test result. No Set H documents have been selected, generated, sealed or run.

## Scope

`tests/corpus/test_audit_mutations.py` generates fully disposable, invented USFM and minimal DOCX files with Python's standard library. It invokes `scripts/corpus/audit-derived-completeness.py` as a separate subprocess (rather than importing its internals) and checks its exit status, JSON `complete` flag and case-level source-reference diagnostics.

Covered positive/negative cases:
- A complete two-verse source/document match (expected pass).
- Dropped `\\mi` continuation; dropped text after a previously unknown `\\zz` paragraph marker.
- Truncated verse, inserted words, reordered words.
- Wrong chapter, wrong verse number, wrong book heading.
- Missing complete verse and an extra document verse.

Test contents are invented tokens, **not scripture from a published edition**. The tests do not open or edit any of the disclosed corpus, publisher documents or historical seals.

## Execute in Codex Cloud / a disposable repo checkout

From the repository root at the exact review commit:

```bash
python3 -m unittest discover -s tests/corpus -p 'test_audit_mutations.py' -v
```

Expected qualification is **all tests passing, every deliberately mutated document rejected, and every report preserving the correct affected reference**. Preserve the test log, exit status, Python version, review HEAD SHA and SHA-256 for the auditor and test script. Do not edit assertions to make an unexpected failure pass; investigate and document it. No GitHub Actions or Windows runner is required.

## Limits

- Only a **USFM→DOCX synthetic qualification**. It does not qualify USFM→PDF, EPUB, authentic publisher files, versification traditions or arbitrary USFM nesting.
- `\\zz` tests one syntactically plausible unknown paragraph marker; it does not establish reliable handling of all marker variants.
- The source/document oracle is generated by test code that was authored alongside this qualification suite, so **this is adversarial unit testing, not independent blinded evidence**.
- A high-quality Set H builder still requires an edition-aligned oracle, pre-seal completeness assurance for actual file formats, document licensing, independent role/access records and approved resource ceilings.
- No candidate recognition code or its freeze SHA is modified by these tests.
