recogniser's code is the same for both rows (`7c7565a`). On the original
corpus the candidate still verifies nine verses whose text differs from
the edition, and that figure stays in every table. v2 is a second
document, scored separately.

## 2. Source-to-document completeness

`scripts/corpus/audit-derived-completeness.py` reads the USFM marker by
marker and the DOCX from `word/document.xml`. It shares no code with the
generator. A paragraph marker it does not know counts as verse text, so a
dropped marker is caught, not excused. It excludes only notes (`\f`,
`\x`), `\w` attributes, and headings, titles and introductions, and it
counts each exclusion by marker (`data/completeness-*.json`). White space
is the only normalisation.

## 5. What the nine are, and are not

* They are a **divergence between the reference and the generated
  document**. The edition's USFM has the words; the v1 document does not.
* The recogniser read v1 correctly. Each verse's verified text is exactly
  what the document says, and the document shows no sign that anything is
  missing: the verse ends at a colon or full stop, and the next verse
  number follows.
* The candidate therefore **cannot detect text missing from an incomplete
  document**, and v2 is no evidence that it can. "Verified" means the
  text was read faithfully from this document with its reference
  assigned. It does not mean the document is a complete or authentic copy
  of its edition. Recognised Scripture stays provisional.
* v1's nine stay counted as wrong verified verses on the original corpus,
  in every report.

## 6. Running v2 with the frozen harness

The harness at `7c7565a` reads its manifests from a fixed list, and
neither it nor `editions.tsv` was changed. v2 is run by placing a copy of
`spablm_usfm_lo.v2.docx` (checksum verified) under v1's file name in a
folder of its own, with `AW_EDITIONS=spablm-docx`:

```
scripts/corpus/run-spablm-docx-derived-v2.sh <harness binary> <corpus folder> <v2 folder> <output folder>
```

The output is labelled `spablm-docx` by the harness; it is v2's, as the
script's checksum line records.
