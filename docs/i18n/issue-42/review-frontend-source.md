# Frontend and generated-output source-context review

The coordinating AI reviewer traced the frontend source candidates separately from the six full locale reads. [Candidate decisions](review-frontend-source-decisions.json) distinguish CSS, developer-only selection diagnostics, programming invariants, logs, product identities and actual generated display wording. These are context classifications, not claims that SQL/CSS or imported writing has received translation approval.

The original inventory is a deliberately broad search aid. Its Rust regular expression can produce cross-string spans; the independent native lexical/context audit supersedes those false positives. The frontend review additionally searched JSX text, accessibility/title/placeholder attributes, dynamic defaultValue paths, raw error rendering and generated document delivery. Single-token protocol values, punctuation, source titles, keyboard symbols and product names were traced in their actual consumers rather than interpreted as untranslated sentences.

| Path/context | Before | Final disposition |
| --- | --- | --- |
| Presentation `exportLocale`, Word `docxFormat` | en-US proofing or system/bare pt overriding the interface variant | Shared formatLocale supplies en-GB/de-DE/ko-KR/fr-FR/es-ES/pt-BR. Paper choice still follows the existing system-region rule. Native English defaults use en-GB. |

| Inquiry shared blocks, about labels and evidence | English compound labels embedding user/source titles and locator text | Optional transient typed display facts are localised; user titles, citations, authors, quotes, printed labels and model-context strings remain exact. No regex rewrites of arbitrary writing. Missing installed Scripture text gets a translated availability message. |
| AI service identity | Generated “Other compatible service” prefix visible beside model | Only that known prefix is localised; exact model suffix retained. Provider brands remain literal identities. |
| Image credits | Generated English “via Wikimedia Commons” wrapper | Transient provenance flag distinguishes app-generated from externally supplied attribution; generated credit joins exact author/licence/provider with the locale separator, supplied/previously stored attribution stays exact. |
| Import format/additional-book warnings | English generated format and canon-name parameters inside translated sentences | Guarded generated-token/code maps use individually reviewed labels; unknown values, imported titles and existing main Bible names remain unchanged. |
| PowerPoint raw XML | English selection-pane/accessibility shape, blank-layout, notes and theme names | ExportLocale labels supply XML-escaped names and proofing language. IDs/schema, notes privacy and user slide content unchanged; exact artifact regressions added. |
| Word raw XML | English custom style names in the Styles pane | Optional transient format labels localise only the nine custom w:name values. Built-in style identities, all style IDs and document body are preserved; escaping and collision tests cover the map. |

All production JSX sentences/ARIA control labels found by this pass resolve through the locale corpus. SelectionSpike is explicitly developer-only (`VITE_SELECTION_SPIKE=1`), has no normal-build surface, and remains a technical diagnostic. Empty image alt values are deliberate decorative-image semantics; BrandLockup is named by its parent. Native file-picker captions/filters are localised by the existing API contract; OS-owned dialog chrome follows Windows settings and is an explicit platform acceptance gap.

Error paths generally use toApiError; fixed kinds, coded errors, plural-only keys and unsupported codes have regressions. PDF.js/plugin technical messages are logged while localised recovery/status copy is shown. `templateSupport` uses already localised API errors; update errors are translated at UpdatesContext. Arbitrary imported source text, Scripture text, user writing, original file names, actual edition copyright/licence metadata and previous material provenance are preserved, even where their original language differs from the interface. The owner-defined diagnostic JSON retains its technical English schema/evidence; visible diagnostic verdict/evidence are localised.
